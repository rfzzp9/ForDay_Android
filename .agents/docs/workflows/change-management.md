# Change Management Workflow

## 목적

작업 중 기존 변경, 사용자 변경, generated 파일, 삭제 파일을 어떻게 다룰지 정한다.

## 먼저 확인할 것

1. `git status --short`
2. 변경 파일이 요청 범위와 맞는지 확인
3. 내가 만든 변경과 기존 변경을 구분

## 기존 변경 처리

- 내가 만들지 않은 변경은 되돌리지 않는다.
- 관련 없는 기존 변경은 무시한다.
- 같은 파일에서 기존 변경과 내 변경이 만나는 경우, 기존 내용을 보존하며 필요한 부분만 수정한다.
- 기존 변경 때문에 작업이 불가능하면 사용자에게 상황을 설명하고 확인한다.

## 삭제 파일 처리

- 파일 삭제는 요청 또는 정리 목적이 명확할 때만 한다.
- 삭제 전 같은 역할이 `.agents/docs/` 등 다른 문서로 흡수됐는지 확인한다.
- 삭제 파일이 많으면 `git status --short`로 목록을 보고한다.

## generated / local / secret 파일

아래 파일은 기본적으로 커밋에 포함하지 않는다.

- `local.properties`
- keystore, secret, token
- release artifact
- generated output
- 임시 `_workspace` 파일

포함해야 한다면 사용자 요청 또는 명확한 이유가 있어야 한다.

## 검증 실패 처리

- 실패한 명령을 숨기지 않는다.
- 실패 원인이 내 변경인지 기존 상태인지 구분한다.
- 원인이 불명확하면 추가 수정 전에 사용자에게 알린다.
- 네트워크/권한 문제는 별도로 명시한다.

## 완료 기준

- 변경 파일이 요청 범위와 맞다.
- 기존 사용자 변경을 되돌리지 않았다.
- 임시/secret/local 파일 포함 여부를 확인했다.
- 삭제 파일의 의도가 설명 가능하다.
